# Контекст проекта: CRM-система для автоматизации аренды оборудования (Rental App)

Этот файл создан специально для загрузки в другие ИИ-модели в качестве системного промпта или базового контекста, чтобы они могли быстро понять архитектуру, стек и реализованный функционал проекта.

## 1. Описание проекта
Это внутренняя монолитная веб-ориентированная CRM-система, предназначенная для прокатных компаний (аренда звукового, светового и сценического оборудования). 
Система позволяет управлять базой оборудования, вести учет клиентов (компаний), создавать сделки (воронка продаж), формировать точные сметы и автоматически генерировать официальные договоры аренды.

## 2. Технический стек (Как реализовано)
*   **Backend:** Python 3 + FastAPI.
*   **Frontend:** Серверный рендеринг через Jinja2 Templates (HTML/CSS/JS). Для стилизации локально используется Tailwind CSS и кастомные стили.
*   **База данных:** SQLite (через SQLAlchemy ORM). Все данные хранятся в одном файле `rental_app.db`.
*   **Генерация документов:** Библиотека `docxtpl` (на базе `python-docx`). Использует шаблоны `.docx` из папки `templates/` и заменяет плейсхолдеры (например, `{{ company_name }}`) на реальные данные из БД.
*   **Интеграции:**
    *   **WhatsApp:** Интеграция работает через стороннее решение **WAHA (WhatsApp HTTP API)**. Приложение общается с запущенным Docker-контейнером WAHA по REST API. Авторизация происходит через генерацию и сканирование QR-кода прямо в интерфейсе настроек CRM. Входящие сообщения принимаются через webhook `/api/wa/webhook`.
    *   **Telegram:** Реализовано через официальный Telegram Bot API (`requests.post`). Токен бота хранится в `.env` файле, настройки редактируются через UI. Входящие — через webhook `/api/tg/webhook` (настраивается кнопкой в Настройках).
    *   **Instagram Direct:** Через Meta Graph API (нужен `IG_PAGE_TOKEN` и `IG_VERIFY_TOKEN` в `.env`). Входящие — через webhook `/api/ig/webhook`.
    *   **AI чат-бот:** Google Gemini REST API (`GEMINI_API_KEY` в `.env`). Модуль `chatbot.py`: отвечает клиентам во всех трёх мессенджерах на основе загруженной базы знаний, по настраиваемому графику работы, «как человек». Fallback по списку моделей (`GEMINI_MODELS`) при исчерпании квоты.
    *   **1С:** REST API для обмена данными: `GET/POST /api/1c/counterparties` (контрагенты), `GET/POST /api/1c/invoices` (счета). Авторизация по заголовку `X-API-Key` (ключ `ONEC_API_KEY` в `.env`, настраивается через UI).
    *   **Push-уведомления:** Библиотека `pywebpush` для браузерных уведомлений.

## 3. Что уже реализовано (Функционал)
1.  **Авторизация и пользователи:**
    *   Система закрыта от неавторизованных пользователей (middleware в `app.py`).
    *   Аутентификация на HMAC-подписанных cookie-токенах (модуль `auth.py`). Пароли — PBKDF2-SHA256 с солью; старые sha256-хэши мигрируются прозрачно при входе.
    *   Лимит — не более 10 пользователей. В админ-панели (`/users`) настраиваются ФИО, роль и **гранулярные права доступа по разделам** (Дашборд, Чаты, CRM, Склад, Задачи и т.д.) — middleware блокирует и страницы, и API.
2.  **Склад (Оборудование) и Каталог:**
    *   Учет остатков, цен, категорий (Звук, Свет, Логистика, Персонал и т.д.).
3.  **Сделки и Клиенты (Воронка продаж):**
    *   Создание карточки клиента со всеми реквизитами (БИН/ИИН, банк, адреса).
    *   Создание сделки, добавление оборудования.
    *   Отслеживание конфликтов (пересечение дат аренды одного и того же оборудования).
4.  **Калькулятор смет (calculator.py):**
    *   Умный расчет стоимости. Скидки применяются **только к оборудованию** и не затрагивают фиксированные расходы (Персонал, Логистика).
5.  **Генерация договоров (document_generator.py):**
    *   Полностью автоматическая генерация файла `.docx`.
    *   Сумма заказа автоматически переводится в текст на русском языке (например, "Две тысячи тенге 00 тиын") с помощью библиотеки `num2words` и кастомной логики обработки копеек/тиынов.
6.  **Уведомления:**
    *   При смене статуса сделки (например, "Оборудование доставлено") клиенту автоматически уходит сообщение в WhatsApp и/или Telegram.
7.  **Единый Inbox (`/inbox`):**
    *   Все переписки из WhatsApp, Telegram и Instagram в одном окне (модель `ChatMessage`), с фильтрами по каналам и отправкой ответов вручную.
8.  **AI чат-бот (`/assistant`):**
    *   Панель управления: вкл/выкл, каналы, график работы по дням недели (с часовым поясом), персона бота, автоответ вне графика.
    *   База знаний: добавление вручную или загрузка файлов (.txt/.md/.docx через `mammoth`).
    *   Тестовый чат прямо в интерфейсе (`/api/bot/test`).
9.  **Кастомные поля сделок (как в Битрикс24):**
    *   Модели `CustomFieldDef`/значения; создание, заполнение и удаление полей прямо из карточки сделки в CRM.
10. **Кнопки перехода в чат:** из карточки сделки/клиента — в WhatsApp (wa.me) и Instagram Direct (ig.me).
11. **Задачи (`/tasks`):** создание, назначение, дедлайны, отметка выполнения.
12. **Аналитика (`/analytics`) и Дашборд (`/`):** реальные метрики из БД — выручка, конверсия, воронка, помесячный график, статистика сообщений по каналам.

## 3.1 Переменные окружения (`.env`)
| Ключ | Назначение |
|---|---|
| `GEMINI_API_KEY` | ключ Google Gemini для чат-бота |
| `GEMINI_MODELS` | (опц.) список моделей через запятую, fallback по порядку |
| `TG_BOT_TOKEN` | токен Telegram-бота |
| `WAHA_URL` | адрес WAHA-контейнера (по умолчанию `http://127.0.0.1:3000`) |
| `IG_PAGE_TOKEN` / `IG_VERIFY_TOKEN` | Meta Graph API для Instagram Direct |
| `ONEC_API_KEY` | ключ для API-обмена с 1С |
| `SESSION_SECRET` | (опц.) секрет подписи сессий; иначе генерируется в `.session_secret` |
| `PUBLIC_URL` | публичный URL сервера (для настройки webhook'ов) |

## 4. Требования к серверу (Рекомендации по деплою)
Для успешного запуска проекта в продакшене требуется:
*   **ОС:** Ubuntu 22.04 LTS или 24.04 LTS.
*   **RAM:** Минимум 2 ГБ, рекомендуется **4 ГБ** (FastAPI потребляет мало, но Docker-контейнер WAHA с эмулятором WhatsApp Web потребляет много памяти).
*   **CPU:** 1-2 vCPU.
*   **Диск:** 20-30 ГБ SSD/NVMe (для ОС, Docker-образов, SQLite и загруженных картинок оборудования).
*   **Программное обеспечение:**
    *   **Docker:** Обязателен для запуска контейнера `devlikeapro/waha` (порт 3000).
    *   **Python 3.10+** с виртуальным окружением (`venv`).
    *   **Nginx или Caddy:** Для Reverse Proxy. Крайне рекомендуется Caddy для автоматического получения бесплатных SSL-сертификатов (HTTPS обязателен для WebPush и безопасности сессий).
    *   **Systemd / Supervisor:** Для поддержания процесса `uvicorn` в рабочем состоянии.
*   **Специфика SQLite:** Так как используется SQLite, обязательно нужно настроить **ежедневное резервное копирование (бэкапы)** файла `rental_app.db` и папки `uploads/` в стороннее облако (Cron-скрипт). Запускать FastAPI нужно с 1 воркером (`--workers 1`), чтобы избежать блокировок БД при записи.
