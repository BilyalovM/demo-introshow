## Краткое резюме встречи

- Два бизнес-потока: **прокат/аренда** и **продажа**; лиды должны разделяться уже на входе (вручную сейчас, позже — чат-ботом).
- До ~**80%** входящих — «шлак» (просто узнать цену); нужна квалификация и отсев в отказ/спам.
- Неинтересные лиды в перспективе отдавать **подрядчикам** с ограниченным доступом и отдельной воронкой; **сейчас — не приоритет**, «потом».
- **Чат-бот** уже в системе: подключить API-ключ (карта/оплата), загрузить прайс в базу знаний, тестировать на **отдельном WhatsApp** до сентябрьского сезона.
- Роли: **менеджер продаж** (считает, согласует, доводит до оплаты) → **менеджер проекта** (получает техничку, собирает команду, выезд).
- Оплата сотрудников: пока договорились идти через **фикс**, а не процент; для маржи временно заложили ориентир **~10%** **[уточнить формулу]**.
- Смета клиенту: нужны два варианта выдачи — **с ценами по позициям** и **без цен (только итог)**; доработать шапку (номер, дата, контакты компании).
- Долгосрочное видение: CRM как **внутренняя экосистема** (лиды → сделки → сотрудники → знания/тесты → бухгалтерия) для масштабирования на города.

## План работ по приоритетам

### P0 — ближайшие 1–2 недели (запуск и ощутимая польза)

1. **Доступ заказчику**  
   Выдать отдельный аккаунт (не админ-общий), собрать фидбек по кликам в CRM / сметах / задачах / «Сегодня».

2. **Настроить воронки под два потока**  
   - Воронка лидов (общая) → успешная стадия создаёт сделку.  
   - Целевые воронки: **Аренда** и **Продажа** (или одна продаж + поле «тип» — **[уточнить]**, на встрече звучало «две воронки»).  
   - Обязательное поле квалификации: аренда / продажа / спам-отказ.  
   - Правила маршрутизации: сайт, карты, WhatsApp, Instagram, ручное.

3. **Чат-бот — подключение и безопасный тест**  
   - Привязать `GEMINI_API_KEY` (оплата с карты заказчика / разработчика — **[уточнить]**).  
   - Загрузить базу знаний: прайс, типовые пакеты (свадьба / площадка / кВт и т.п.).  
   - Тумблер «не уходить с темы» (на встрече — ограничить оффтоп).  
   - Тест на **вторичном WhatsApp** 5–7 дней → только потом на основной номер.  
   - Цель до сентября: квалификация + черновые цены + заполнение полей лида.

4. **Смета клиенту — два режима выдачи**  
   - Кнопки: «с ценами по позициям» / «без цен, только итог» (для гос/«важна только сумма»).  
   - Сейчас unit-prices на клиентской смете уже скрываются частично — довести до явного выбора заказчика.

5. **Шаблон сметы под образец Intro Show**  
   - Номер сметы + дата составления.  
   - Контакты компании в шапке.  
   - Смены / дни (поле уже есть — проверить отображение в DOCX/PDF).  
   - Название проекта — по желанию убрать, оставить номер **[уточнить по образцу]**.  
   - Получить эталонный файл от заказчика и подогнать вёрстку.

6. **Фикс менеджеров в сделке (минимальная модель)**  
   - Зафиксировать в карточке/ведомости: фикс менеджера продаж + фикс менеджера проекта (суммы вводит менеджер).  
   - Проценты «кто сам привёл» — отложить.  
   - Временно заложить ориентир маржи **10%** как параметр, не как жёсткую бизнес-логику.

### P1 — следующие 2–4 недели (операционка и контроль)

7. **Робот-напоминания (не AI)**  
   Если сделка без движения > 24 ч → автосообщение ответственному (внутри / WhatsApp — **[уточнить канал]**): «не забудьте про сделку».  
   Аналогично — эскалация по просроченным задачам (часть уже есть в UI задач).

8. **Разделение ролей «продажи» vs «проект»**  
   - В сделке явно: кто продал / кто исполняет.  
   - Техничка и сбор команды — зона менеджера проекта.  
   - Логистика в смете — по словам заказчика, не зона sales-менеджера.

9. **Договор субаренды**  
   Отдельный шаблон DOCX + пункт/пометка субаренды в клиентском пакете.  
   Онлайн-наличие склада подрядчиков — **не делать сейчас** (устно/по телефону).

10. **Чат-бот → CRM**  
    Автосоздание/дозаполнение лида из переписки (имя, что нужно, аренда/продажа), уведомление менеджеру.

11. **Оценка и дробление оплаты разработки**  
    На встрече договорились оценивать работу **пакетами/этапами**, а не одной большой суммой.  
    После P0 — зафиксировать границу этапа и стоимость следующего пакета.

### P2 — горизонт (осень / после стабилизации города)

12. **Подрядчики / «гости»**  
    Отдельная воронка + ограниченные права + видимость переписки для контроля; компенсация за переданные лиды.

13. **Внутренняя «школа» сотрудников**  
    База знаний → тесты → техника безопасности → допуск к смене / влияние на ставку.  
    Официальные «корочки» (электрик, высотники) — учёт в карточке сотрудника.

14. **Оргструктура под мультигород**  
    Сначала отладить один город как эталон, затем копировать регламент.  
    Блок «Орг → сотрудники» со схемы.

15. **Бухгалтерия / 1С глубже**  
    После того как CRM-контур стабилен (на встрече — явно «после»).

16. **Продажный каталог отдельной компании**  
    Свой прайс → пересчёт в смету «как своё». Пока база большая и «не провалится» полностью — модуль временный **[уточнить приоритет]**.

## Пояснение схемы с фото (как ложится на CRM)

Схема в блокноте (упрощённо):

```text
Сайт (~80% качества?) ──► Лиды «Ли» ──► Сотрудник / ответственный
                              │
                    ┌─────────┴─────────┐
                 Аренда «Ар»         Продажа «П»
                    │
              Мех / Мех·R   ← полевые роли
                    │
              Ф / %         ← фикс или процент (пока фикс)
                    │
              30/60 ──► Смена ──► Ц / П   ← смена, цена, платёж
Орг ──► Сотр
```

| Элемент схемы | Как в CRM сейчас / что делать |
|---|---|
| **Сайт** | Источник `site` + публичная форма `/lead`; карты — `maps`. На встрече: сайт/поиск/карты — качественный трафик vs Instagram. |
| **«Ли» (лиды)** | Воронка `kind=lead`, стадии, отказ/успех → сделка. |
| **«Орг» / «Сотр»** | Пользователи + права; дальше — оргструктура и роли (P2). |
| **«Ар» / «П»** | Две целевые воронки или тип сделки (P0 настройка). |
| **«Мех»** | Назначение в команде сделки + строки «Персонал» в смете/ведомости. |
| **«Смена»** | Поле `shifts` в сделке/смете (дни/смены) — уже есть. |
| **«Ф / %»** | Модель выплат: на встрече решили стартовать с **фикса**. |
| **«30/60»** | На аудио как «30/60» **явно не произнесено**; на схеме есть. Возможные смыслы: разрез фикс/переменной, смены, или доля — **[уточнить у заказчика]**. |
| **«Ц / П»** | Цена смены и выплата/платёж в зарплатной ведомости. |
| **«Люберецко» / «соб/рек»** | По фото не удалось надёжно прочитать/сопоставить с речью — **[уточнить]** (локация? пометка «собственный / рекомендованный»?). |

**Сквозной поток, который презентовать:**  
Сайт/мессенджер → лид → квалификация (аренда/продажа/отказ) → сделка → смета → команда и смены → техничка/задачи → авансы и ведомость → (позже) подрядчики и школа сотрудников.

**Жёсткий внешний якорь:** до **сентября** — протестированный письменный бот на демо-канале, чтобы не ломать основной WhatsApp в сезон.

**Блокеры со стороны заказчика (критично запросить сразу):**
1. Образец сметы/КП и желаемый вид «с ценами / без цен».  
2. Карта/бюджет на Gemini + тестовый номер WhatsApp.  
3. Список стадий лидов и двух потоков (аренда/продажа).  
4. Расшифровка схемы: что такое **30/60** и пометка внизу фото.  
5. Суммы фиксов для менеджера продаж и менеджера проекта.

## Открытые вопросы к заказчику

1. Воронки: две отдельные (Аренда / Продажа) или одна с полем «тип»?  
2. Что означает блок **30/60** на схеме (доля, смена, оплата)?  
3. Формула маржи: выручка − субаренда − ФОТ − расходы − налог? Куда входит «10%»?  
4. Фиксы: кто именно получает (sales / project / механик) и типовые суммы?  
5. Напоминания 24 ч: только внутрь CRM или ещё WhatsApp сотруднику?  
6. Подрядчиков подключаем в каком месяце (ориентир)?  
7. Продажный каталог «чужой компании» — нужен в P0/P1 или можно позже?  
8. Кто оплачивает токены Gemini и на чью карту вешается ключ?  
9. Нужен ли отдельный шаблон **договора субаренды** в ближайшем пакете?  
10. Расшифруйте нижние пометки на фото схемы («Люберецко», «соб/рек» — если это не ошибка чтения).
