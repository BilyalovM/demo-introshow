# Multi-city (лёгкий фундамент)

Intro Show CRM готовится к масштабированию по городам **без** полного multi-tenant rewrite.

## Как устроено

- Одна БД, общий каталог оборудования.
- Справочник `cities`: `id`, `name`, `slug`, `is_active`, `timezone`, `sort_order`.
- Сиды: **Алматы** (активен по умолчанию), **Астана** и **Шымкент** (неактивны, готовы к включению).
- `Deal.city_id` — город сделки (nullable → при миграции заполняется Алматы). Текстовое `Deal.city` синхронизируется с названием для документов/шапки сметы.
- `User.city_id` — домашний город сотрудника (опционально).
- `WorkSession.city_id` — город смены (берётся из активного города при старте дня).
- Настройка `app_settings.active_city_id` + cookie `active_city_id` — текущий город сессии.

## Кто что видит

| Роль | Переключатель городов | Фильтр CRM / сегодня / аналитика |
|---|---|---|
| admin / manager | все **активные** города | по выбранному городу (`city_id=0` в CRM = все) |
| сотрудник с `city_id` | только свой город | свой город |
| сотрудник без `city_id` | все активные | выбранный / дефолт |

Подпись в сайдбаре: `CRM · {текущий город}`.

## Управление

- **Настройки → Города CRM** (admin): добавить / переименовать / вкл-выкл.
- Карточка сделки и шапка сметы: выбор города из справочника.
- Сотрудники: поле «Домашний город».

## Что фильтруется

Сделки (CRM, дашборд, аналитика), назначения «Сегодня», рабочие смены — по `city_id` (NULL считается «своим» городом после backfill и попадает в текущий фильтр).

## Не входит в MVP

Отдельные БД/тенанты, разный каталог по городам, биллинг per-city, timezone-aware календарь (timezone хранится, но день смен пока в логике Алматы UTC+5).
